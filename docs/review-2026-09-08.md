# Code review and bug fixes — 8 September 2026

Historical report for the reviewed source snapshot. Later Telegram, observability and package-layout changes are covered in [current acceptance status](acceptance.md); counts and migration references below describe this review's build.

Base: `main` / `origin/main` at `2664e14`, fetched again after validation. The working tree was clean before review. The review focused on durable job admission/recovery, cancellation, delivery/reconciliation, native protocols, tool identities and environment boundaries, with supporting inspection of storage, memory/context, scheduling, artifacts, operations and supervision.

## Fixed findings

| Bug and observable failure | Fix and evidence |
| --- | --- |
| Cancelling a job while a multipart send is in flight leaves later chunks eligible to send. Rate-limit retries can also revive the cancelled send. | Cancel unsent chunks regardless of the action's current state. Recheck cancellation before retry. Aggregate action state without hiding remote uncertainty. Regressions cover accepted, rejected, uncertain and confirmed-no-effect outcomes. |
| Reconciliation records a remote receipt but omits the final assistant message from canonical conversation history. | Normal dispatch and reconciliation share receipt/finalization logic. Single- and multipart replies enter history exactly once after every chunk succeeds. |
| Backup restore marks an action uncertain while its chunks remain ready, making reconciliation impossible. Multiple uncertain chunks have no operator selection mechanism. | Restore marks every unconfirmed chunk uncertain. `actions inspect` includes chunks; `actions reconcile --delivery-id` selects the exact one. Other uncertain chunks continue to block dispatch and quarantine release. A real backup/restore regression reconciles a multipart action and releases quarantine. |
| Retrying a failed interactive job uses the default background lane, so the default background pause strands it. | Retain the original lane and parent relationship when creating the retry. The CLI regression claims the replacement from the interactive queue. |
| Model pause repeatedly claims and interrupts inference jobs, consuming attempt counters without doing work. | Admission checks the pause transactionally; inference remains queued while reminders continue to run. |
| Slow media preparation or local embedding loading outlives the initial 60-second job lease before heartbeats start. | Start renewal before input preparation. A synchronized regression advances a fake clock beyond the initial lease while preparation is in progress. |
| Identical outbound tool requests to different recipients collide under one semantic key. | Include explicit recipients in the tool identity, preserving idempotence for repeated requests to the same recipient. |
| Claude cannot find the existing subscription login in the sanitized worker environment. | Set `USER` and `LOGNAME` from the effective or configured runner UID, without inheriting arbitrary host environment values. Locally reproduced absent/present login behavior; offline tests cover both current and dedicated runner identities. |
| Codex returns a completed turn after refusing Theo MCP calls under its native `never` approval policy. | Configure approval for the known Theo broker tools specifically. Native sandbox restrictions and denial callbacks remain in place; broker grants and durable external-action approvals continue to govern effects. The initial live case failed despite a completed native turn; the final suite requires actual committed tools. |
| Codex concatenates progress commentary with the final answer. | Prefer completed `agentMessage` items marked `final_answer`, retaining delta fallback for runtimes that omit phases. An offline subprocess fixture reproduces the unwanted concatenation. |
| Relative reminder requests have no application clock in model context. A live 15-minute reminder was scheduled 42 seconds after its intended due time and did not fire at that time. | Include the current Unix time, UTC time, owner-local time and timezone in every canonical context. The live rerun fires exactly at the expected application time while models are paused. An offline test verifies owner timezone and clock advancement. |
| Codex says delegation is queued after using its own subagent mechanism; Theo has no durable child job or completion obligation. | Disable native collaboration, goals, automation, memory and effect features in the adapter and direct work through Theo MCP. A live rerun creates the actual child job, executes it, registers a verified artifact and delivers the originating conversation's final answer. |
| Process cleanup returns when the native session leader has already exited, or leaves a stubborn child alive after the leader accepts SIGTERM. | Always clean up the owned process group, including surviving children, and make repeated cleanup safe. Two real subprocess regressions cover an exited parent and a child that ignores SIGTERM. |
| Claude answers “saved” after writing workspace Markdown memory files, leaving Theo's searchable memory empty. | Disable Claude auto-memory for adapter sessions and supply a shared worker instruction requiring Theo's memory tools and verified receipts. The natural-language live memory request exposed this; the earlier smoke test's restricted tool list could not. |
| A schedule receipt returns only an ID, so the answer can say a recurrence starts immediately even though its first occurrence is two hours away. | Return the persisted kind, timezone, Unix due time and local ISO due time with the schedule ID. A broker regression verifies these values against the actual saved occurrence. |

Complex transcript review also found ordinary confirmations exposing internal IDs and tool statuses, unsolicited prose outside requested JSON, an unsupported dollar denomination, and advice to retry a still-uncertain send. The shared voice instruction now asks for plain-language outcomes, retaining technical details when requested or needed, and avoids invented emotional reassurance. Worker instructions preserve supplied units and require evidence about the exact action before recommending a retry. Revision changes are distinguished from errors in earlier answers; requested JSON keys exclude unsolicited commentary. The trusted persona/voice now travels in native instructions separately from user and recalled content; a regression verifies that untrusted content never enters that field. Claude uses Theo's worker system prompt rather than appending it to the native coding prompt. The newer local behavior suite records actual answers and requires a separate subjective review rather than assigning personality a pass from an exit code.

Native probes now renew their leases and stop owned processes on timeout. The supervisor test checks actual Unix-socket binding before deciding whether the host supports the integration, avoiding a misleading timeout in restricted environments.

The Codex configuration uses documented [per-tool MCP approval overrides](https://learn.chatgpt.com/docs/config-file/config-reference). Final message selection follows the installed app-server schema and [app-server event contract](https://learn.chatgpt.com/docs/app-server).

Native capability flags were checked against the installed Codex feature inventory and its configuration reference. Claude's session setting follows its [auto-memory documentation](https://code.claude.com/docs/en/memory). These overrides apply only to Theo's child runtime sessions; they do not change the operator's global settings.
